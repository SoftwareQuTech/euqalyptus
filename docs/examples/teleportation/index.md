# Teleportation

A two-program example: **Alice** (the sender) and **Bob** (the receiver). Together they implement quantum teleportation of a single qubit.

![Teleportation flow](../../assets/figures/entanglement-flow.svg)

The two programs run on different nodes and only communicate via:

- An **EPR pair** generated by `Entangle("…")` on each side. The runtime arranges the entanglement under the hood.
- A **classical channel** carrying the two correction bits from Alice to Bob.

## Files

The two programs live in `qoala-compiler/teleportation/`:

| File | Role |
| --- | --- |
| `teleportation/alice.py` | Sender. Holds the qubit to teleport, performs the Bell-state measurement, sends the correction bits. |
| `teleportation/bob.py` | Receiver. Receives the corrections, applies them conditionally, measures the recovered qubit. |

In the docs, those become:

- [Sender](sender.md) — fully documented walkthrough.
- [Receiver](receiver.md) — *currently a stub*, see the page for context.

## Why two programs?

The Qoala execution model assumes each network node runs its own program independently. The two programs declare each other as their `Remote(...)` and exchange information through entanglement and classical send/recv. There is no shared address space; every value the receiver acts on either came from a measurement it performed locally or from a `recv_int` it executed.

## Run them

```sh
python teleportation/alice.py
```

prints Alice's HIR module on stdout. Same for `bob.py`. Each module is emitted with `singular_comm_ops=True` so the classical send/recv ops are already in single-value form.

To take either through the rest of the pipeline, see [Continuing the pipeline](../../continuing-pipeline.md).
